# 离线公交换乘规划器

基于 React + TypeScript + Vite 的纯前端公交换乘规划器。行程选择依据**班次到发时刻**而非站点距离，所有计算都在浏览器本地完成，不接入地图或任何在线交通服务。

## 启动方式

使用 Node.js 22（项目随附 22.16.0 工具链时可先加入 PATH）：


## 数据格式（JSON 路网）

导入的 JSON 顶层包含 `stations`（站点）与 `trips`（班次）两个数组。所有时刻均为**运营日零点起的整数分钟数**，允许超过 1440 以表示跨午夜（如 1500 = 次日 01:00，界面显示为 `01:00(+D1)`）。

```json
{
  "stations": [
    { "id": "A", "name": "东岗", "minTransferMinutes": 0 },
    { "id": "C", "name": "大学城", "minTransferMinutes": 3 }
  ],
  "trips": [
    {
      "id": "L1-01",
      "lineName": "1路",
      "stops": [
        { "stationId": "A", "arrival": 480, "departure": 480 },
        { "stationId": "C", "arrival": 500, "departure": 502 }
      ]
    }
  ]
}
```

字段说明：

- `stations[].id`：站点唯一 ID；`name` 为显示名；`minTransferMinutes` 为该站**中途换乘**所需最短分钟数（非负整数）。
- `trips[].id`：班次唯一 ID；`lineName` 为线路名；`stops` 为按行驶顺序排列的停站。
- `stops[].stationId` 必须引用已声明的站点；`arrival` / `departure` 为到/发时刻。

校验规则（任一不满足都会在页面上按 JSON 路径列出错误，例如 `$.trips[0].stops[1].arrival`，且**保留原路网不替换**）：

- 站点 ID、班次 ID 不得重复；停站必须引用存在的站点；同一班次不得重复停靠同一站。
- 所有时刻与最短换乘时间必须是非负整数；站内发车不得早于到达。
- 相邻停站之间行驶时间必须为正（下一站到达必须严格晚于本站发车）。
- 班次至少包含 2 个停站；JSON 语法错误同样会给出明确提示。

## 核心操作

1. 页面默认载入**内置示例路网**，包含 7 个站点、4 个班次，覆盖：
   - 直达：东岗 A → 北站 G（1路 L1-01/L1-02）。
   - 换乘：A → 机场 E，需在大学城 C 换乘（C 最短换乘 3 分钟）。
   - 跨午夜：夜间3路 N3-01，南苑 F 23:00 发车，经 C、E 于次日 01:00 到体育馆 D。
2. 选择起点、终点、出发时刻（HH:MM）与最多换乘次数，点击“规划行程”。
3. 结果区按乘车段展示线路、班次、上下车站及到发时刻；列出初始候车与各次换乘等待、最早到达、总耗时、换乘次数与班次序列；站点示意图中高亮实际经过的边与站点。
4. 修改查询条件或路网后结果立即清空，需重新规划，不会展示过期结果。

### 选路规则

算法在“车站等待”与“在乘班次”两类状态上做标签化搜索：

- 目标为**最早到达**；到达时刻相同则换乘次数更少；再相同则班次 ID 序列字典序更小。
- 同一班次继续乘坐不算换乘，改乘其他班次才算；首次上车不扣换乘时间。
- 中途下车后须满足下一班发车时刻 ≥ 到达时刻 + 该站 `minTransferMinutes`（恰好满足即可登车）；起点候车只需发车时刻 ≥ 出发时刻。
- 每个在乘班次独立保留状态，因此不会因为某站“更早到达”而丢弃虽然晚到该站、但仍能直达终点的乘车状态。
- 起终点相同时返回零乘车行程；换乘次数上限内无可行班次时明确提示“无可行班次”。

## 代码结构

- `src/types.ts`：数据与结果类型。
- `src/sampleNetwork.ts`：内置示例路网。
- `src/validation.ts`：JSON 解析与逐路径错误定位。
- `src/planner.ts`：时刻换乘规划算法。
- `src/time.ts`：时刻/时长格式化（跨午夜标记 `+Dn`）。
- `src/App.tsx`、`src/NetworkDiagram.tsx`：页面与站点示意图。
- `src/*.test.ts`：校验与算法的单元测试。
